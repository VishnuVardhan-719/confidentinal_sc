## Resolved ambiguities

1. Shared feature gates permit reads/closeout while off, unlike P01's fail-closed
   read requirement. Retain P01 settings and their append-only change ledger;
   RLS reader predicates also enforce the gate. No shared gate semantics changed.
2. Section 4.1's no-self-review CHECK conflicts with section 7's collector self-void.
   Permit self-review metadata solely for an own reported claim's void; confirmation,
   dispute and supersession still require an independent reviewer.
3. Section 5.2 permits disputed→confirmed, while the reconcile prose only lists
   reported claims. Allow finance to confirm disputed claims so the machine has a
   usable remediation edge; payment remains disputed until explicit resolution.
4. Intake-review/resolution reasons use the app's closed collection-reason list.
   Exceptions use `raised_at` as `reportedAt` and as their finance cursor timestamp.
5. A terminal backfill booking without its matching version/state event stops the
   migration for review. No guessed deadline or renewed reporting window.
6. Bounded worker scans alternate phases; callers repeat manual passes to cover
   both queues. Private typed-time primitives capture one DB time per production
   decision/pass and allow deterministic privileged boundary verification.
7. Existing membership management only delegates scopes the owner already holds.
   Because finance:collect is intentionally bootstrapped to nobody, the first org
   collector grant needs reviewed owner/bootstrap SQL; no management bypass added.
