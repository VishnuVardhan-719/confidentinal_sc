Shared objects are called by their exact signatures:
- create goes through `create_request_core` (lead and horizon from the lab policy);
- terminal steps go through `assignee_finish` (lab path `release`);
- absence uses `open_exception('absence_reported')` and then `finish_assignments`;
- no-show is ops only, through `ops_close_booking` (OD-1);
- technician contact comes from the shared `get_assignment_contact` (route `POST /api/bookings/:id/contact` from feat/P5-shared-api; not re-created).

No generic RPC is replaced. The order inside every command follows §13.1: shape checks, hash, replay, live authorization, gate, locks (booking, provider, resources, `lab_orders`), replay again, recheck, version, state, mutation, `record_request`.

## Contract/design conflicts and findings

1. **Shared defect in `booking_private.in_schedule`** (`202611170005_b01_booking.sql` L229): `e.period && period` resolves `period` to the column (a column wins over a SQL-function parameter), so any blackout row disables the resource for all time. This affects doctor, care and lab accepts and slots. Fix in a shared file (001591+): `e.period && in_schedule.period`. 042's blackout case passes either way.
2. Steps after a terminal state return 42501, not the design's 55000: §13.1 puts live authorization before state checks, and the assignment has ended.
3. The `collected` milestone needs the live assignee predicate; only `handed_over` and the two failures accept closeout (§5.2 list). A sample collected but unreported when the window closes can only be closed as `collection_failed`, or by ops.
4. Design §8.2 timeline `{to_state, reason, occurred_at}` became `{reason, occurred_at}` (§8.5).
5. The design's 0A000/"all lab routes 503" and route 404 rules are superseded by §10.1. Implemented per the contract.
6. MR-08's "ignore past-start requests" branch cannot be observed: with a 30-minute test and a 120-minute lead, a past request can never overlap a new one. It is noted in 041.
