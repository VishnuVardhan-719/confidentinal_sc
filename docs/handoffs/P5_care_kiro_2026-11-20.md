## Conflicts found

1. **Shared suites 021, 024, 027 vs the contract's care accept check (§7.2).** They accept caretaker bookings with `pg_temp.p5_accept` on the p5s caretaker service, which has no task list, so the accept check raises `55000 care_plan_missing`. `3a88e5a` made `p5_step` and `p5_raw` switch category guards off, but `p5_accept` still calls `accept_booking` with them on. Shared fix: wrap `p5_accept`'s `accept_booking` call in `pg_temp.p5_category_guards(false)` / `(true)`, as `p5_step` does. Seeding a task list for the p5s caretaker service `c4100000-0000-4000-8000-000000000004` in `_p5s_fixture.inc` would also work, but it changes what every shared caretaker booking carries.
2. **Design E2/T02 vs shared regression suites.** The design rejects a request on a service without a task list (`care_scope_required`). Suites 013 and 023 create caretaker requests on unscoped services through the public create, and 020, 022, 025, 026 and `run_p5s_concurrency.py` insert unscoped caretaker bookings directly; a strict trigger fails all of them. The trigger therefore admits an unscoped request without a plan; acceptance refuses it (`care_plan_missing`), `get_care_plan` hides it and `get_care_service_tasks` returns `P0002`, so no unscoped care work can be accepted. To restore the design's request-time refusal, the shared suites need task lists for their caretaker services, then a care fix file (`001930`+) can raise in the trigger.
3. Design T19/E8/E9 (nobody can close a session after suspension or past the window) vs contract §5 and §6: built per the contract (closeout plus ops).
4. Design §6.1 (only create is keyed; retries get `40001`) vs contract §13.2: built per the contract; all four care commands and the setter take `p_request_key`.
5. Design §6.3 runs the accept check before reservations; the contract's trigger placement runs it after `accept_booking` inserts them, so `23P01`, `resource_busy` and `schedule_changed` take precedence over care errors. No safety change; the transaction rolls back either way.
6. Contract §7.2 names two BEFORE triggers; the orchestrator rule (`<prefix>_<cat>_booking_guard`) is met with one trigger, `p5c_care_booking_guard`, that runs both hooks.
7. Contract §8.5 makes `get_care_plan` the patient timeline source, so it adds `state` and `timeline` to the design's field list.
