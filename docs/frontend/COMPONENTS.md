## Owned composition boundaries

Codex C supplies ProviderCard/profile presentation, directory filters/results, BookingSummary/Timeline/Actions, patient cards and page composition in src/components/directory, booking and patient. Shared primitives must accept props such as formatted price + unit, status label/tone, issue code, loading/disabled reason and callbacks, not service-role records or authorization decisions.

The existing modules expose immutable subscribable controller snapshots, a pure wizard reducer, URL draft helpers and request-scoped loaders. Shared components must not add a second persisted copy of these states. While directory phase is loading with an old page, mark it stale and prevent actions using those old results. An uncertain submit permits explicit reconciliation only; a known booking with changed offer must stay attached to its existing ID, not start another intent.

Typography/spacing/colors come from the foundation's approved tokens. At least heading/subheading/body levels, a consistent 4/8 spacing scale, purposeful surface/status colors and visible focus are needed. Contrast and script shaping still require actual browser review after components exist; this ledger is not design verification.

## Proposed E2E semantics for coordination

Use semantic roles/names first. tests/e2e/README.md lists proposed stable IDs for async regions and business-state projections. Essential shared hooks: fixture-notice, gate-notice, form-error-summary, offline-banner, profile-completion, private-access-denied. Stepper: booking-progress list; one item with aria-current=step and data-step=<canonical step>. These test IDs never contain private values. Agree final exports and accessible English names before removing fixme; locale labels belong in message files, not hardcoded JSX.

The new specs remain test.fixme because pages/guards and scenario lifecycle do not exist on this branch. The foundation/lead also needs:

- Approved @playwright/test dependency, browser setup and Playwright config with tests/e2e/*.spec.mjs discovery. No package/config change is made by this task. Pending JavaScript specs avoid an unresolved TypeScript dependency; migrate to typed Playwright fixtures once the package lands.
- Isolated fixture-app scenario/reset lifecycle, controllable clock/delayed responses, and a real app observation bridge (E2E_APP_OBSERVER_MODULE) implementing begin/settle/dispose. The bridge must count module create invocations across server/client paths and drain reconnect/late completions before assertions; one persisted booking alone does not prove one request. The helper's E2E_FIXTURE_SCENARIO equality check does not implement seeding. No shared mutable DB, production test-control route or fake role cookie.
- Actual authorized synthetic patient/provider sessions, with local ignored storage-state files from the auth harness; direct-route and wrong-role tests must exercise the real guard. Fixtures do not count as RLS/real integration evidence.
- Reviewed server offer/policy/consent preparation, cancellation quote, scoped action grants and the missing timeline/payment/profile/record/support contracts recorded in REQUESTS.md. Never enable a real transaction from browser-only schema flags.

Handoff: fe-a can report which request IDs are already exported, the import paths, approved selector/name changes, and unresolved dependencies. Shared component completion alone does not close FE07–FE09; actual pages, responsive/a11y browser checks and integrated authorization evidence remain separate gates.
