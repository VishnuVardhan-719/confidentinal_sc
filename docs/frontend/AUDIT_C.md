# Adversarial self-audit, fe-c areas (PHASE R9-C)

Branch `feat/fe2-c`, 2026-11-19, by fe-q. Scope: public doctor directory and profiles (`/doctors/**`), the doctor booking journey (`/patient/book/**`), patient lab tests, caretakers and scheduled ambulance transfers (`/patient/{lab-tests,caretakers,ambulance}/**`) and their modules and components. Code owned by other agents that is present on this branch was scanned too; findings there are listed for their owners and not changed, with one exception noted below.

Status words: PASS (checked, holds), FIXED (violation found and fixed, with a test), OPEN (known gap, not fixable here), BLOCKED (depends on another branch).

## Results

| # | Invariant | Status | Evidence |
|---|---|---|---|
| 1 | No PHI or private ids in URLs, localStorage or sessionStorage | PASS | No source file uses `localStorage` or `sessionStorage` (static scan in `tests/unit/modules-services/invariants-c.test.ts`). fe-c links and redirects use only public ids or filters in the query string (`providerId`, `serviceId`, `pin`, `speciality`, `sort`, `showFull`, `availability`, `next`), checked by the same test and by `a11y-sweep-c.spec.ts` on every visited page (storage empty, no other query keys). Request and booking pages use the server's opaque UUID in the path, which carries no personal data. Notes, addresses, tests and times stay in component state (`expectNoPrivateDraft` in the journey and service specs). Location coordinates never reach the URL (`doctor-search.spec.ts`). |
| 2 | Money only integer paise, shown in Indian format | PASS | `formatPaise` refuses fractional and negative values and gives `₹12,34,567.50` in en, te and hi (test). Every synthetic price is an integer number of paise (test). The server recomputes totals and refuses a changed total with 409 (unit tests per module). No rupee float maths in fe-c code (static test). For fe-e: `src/components/lab/lab-views.tsx` turns `pricePaise / 100` into a `toFixed(2)` input value for the lab catalogue editor; it should convert back with integer maths. |
| 3 | Times stored UTC, shown in Asia/Kolkata | PASS | Schemas use `utcSchema`; `formatDateTime` and the slot picker format with `timeZone: "Asia/Kolkata"`; fixture slots are `Z` instants on the advertised IST times (tests). |
| 4 | Booking, payment and clinical states are separate badges | PASS | Every request and booking page shows three badges from three label families (`booking.status.*`, `payment.status.*`, `services.*.record` or visit record); asserted in unit tests and in every e2e happy and decline path (`expectBadges`). |
| 5 | Live payments disabled | PASS | No gateway or payment-order call anywhere in `src` (static scan). Payments HTTP adapter fails closed (test). Forms show "Pay after the service" and "Online payment is not available yet"; the doctor wizard's online option is a disabled radio. |
| 6a | Server-side session check on every protected fe-c route and action | PASS | Every page and server-action file under `/patient/{book,lab-tests,caretakers,ambulance}` calls `getPatientSession()` on the server and none is a client component (static test, 14+ files). Every server action re-checks the session. http mode is always unauthenticated and redirects to login. |
| 6b | `requireRole` on protected routes | BLOCKED | `requireRole` lives in `src/modules/auth` on `feat/fe2-b` and is not on this branch. fe-c uses the interim server-only `getPatientSession()` (fixture-only, never production). Integration should swap it for `requireRole("patient")` in the files the static test lists. |
| 6c | Owner check on reads and mutations | FIXED | The service-request fixture returned and cancelled any record by id. `get`, `list` and `cancel` now only see records of patients the account may act for (self, or family with booking permission); others are "not found". Test: "a service request of another patient is not visible or cancellable". |
| 6d | Owner check on doctor bookings | OPEN | The B01 booking DTO has no patient owner field, so the frontend cannot check it; the backend must scope bookings to the session (RLS). The fixture has one synthetic account. |
| 7 | Ambulance: emergency notice and no dispatch | PASS | All three ambulance pages and their error page start with "Emergency? Call 112 now" and a `tel:112` link (e2e and static test). The form needs "this is a planned transfer, not an emergency". No dispatch, ETA or tracking UI exists in fe-c code (static test, e2e text check). Ops-side emergency dispatch (fe-e) is a hard-gated placeholder. |
| 8 | Accessibility of owned routes, 390px and 1280px | FIXED | The sweep found the public header overflowing at 1280px in Telugu (12 px). Fixed in `src/components/shared/public-header.tsx` (fe-a's file, one class: logo margin at `xl` from 24 px to 8 px). The sweep now covers te and hi directory and profile pages. |
| 9 | Request times that cannot be served | FIXED | The caretaker form offered start times that a longer shift would run into the next booking, so the patient got repeated "Something changed" refusals. Hours are now chosen before the time and only start times that fit the whole shift are offered. Test: "with the shift length known, start times that would run into another booking are not offered". |
| 10 | No hard-coded English in fe-c components | PASS | See step 3 of the task report; a static test guards JSX text in fe-c components.
